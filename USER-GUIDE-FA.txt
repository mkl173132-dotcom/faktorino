فاکتورینو — گزارش امنیت و استقرار این بسته
============================================

انجام‌شده در این نسخه
--------------------
1) مسیرهای ثبت و حذف Passkey که قبلاً فقط userId ارسالی مرورگر را ملاک قرار می‌دادند، تا زمان وجود نشست احراز هویت‌شده سرور غیرفعال شدند. این کار جلوی تغییر Passkey حساب دیگران با جعل userId را می‌گیرد.
2) اعتبارسنجی challenge و امضای WebAuthn برای ورودهای Passkey موجود حفظ شده است.
3) محدودیت اندازه JSON، هدرهای امنیتی، CORS محدود، rate limit و پاک‌سازی challengeهای منقضی اضافه/سخت‌گیرانه‌تر شد.
4) آدرس IP برای محدودسازی از req.ip پشت یک reverse proxy مورد اعتماد خوانده می‌شود؛ X-Forwarded-For خام دیگر مستقیماً مصرف نمی‌شود.
5) اگر فایل پایگاه داده خراب باشد، سرور متوقف می‌شود و به‌جای ساخت پایگاه خالی، اطلاعات قبلی را بی‌صدا بازنویسی نمی‌کند.
6) فایل‌های آیکون از 1254 به 512 پیکسل کاهش و PNG بهینه شد؛ آیکون PWA با اندازه واقعی هماهنگ شد.
7) فایل‌های قبلی پروژه حفظ شده‌اند.

محدودیت‌های مهم — هنوز برای اطلاعات مالی واقعی/استفاده عمومی تأیید نشده
-----------------------------------------------------------------------
- ثبت‌نام و ورود اصلی حساب فاکتورینو همچنان در مرورگر و localStorage انجام می‌شود؛ این نسخه آن را به ورود سروری امن تبدیل نکرده است.
- داده‌های مشتری، فاکتور، هزینه و انبار در این پروژه عمدتاً محلی هستند. این تغییرات همگام‌سازی امن چنددستگاهی یا پشتیبان‌گیری ابری ایجاد نمی‌کند.
- ثبت Passkey جدید و حذف Passkey سمت سرور موقتاً بسته است تا وقتی سامانه ورود حساب به نشست امن سرور متصل شود. Passkeyهای قبلی (در صورت وجود) فقط مسیر احراز هویت فعلی خود را دارند و ورودشان به‌تنهایی نشست حساب ابری ایجاد نمی‌کند.
- API فعلی صرفاً سرویس WebAuthn است و API کامل حساب/فاکتور محسوب نمی‌شود.
- URL فرانت‌اند و RP_ID در render.yaml نمونه تنظیمات فعلی پروژه‌اند؛ قبل از Deploy باید با دامنه واقعی خودتان تطبیق داده شوند.
- Render Persistent Disk در پلن‌های پولی ارائه می‌شود. فایل render.yaml از پلن starter و دیسک /var/data استفاده می‌کند؛ قبل از ساخت سرویس، هزینه جاری را بررسی و با مالک پروژه هماهنگ کنید. هیچ سرویسی از اینجا Deploy نشده است.
- config.js آدرس پیش‌فرض سرویس Render را دارد؛ پس از Deploy باید با URL واقعی نمایش‌داده‌شده در داشبورد Render تطبیق داده شود.

مراحل استقرار
-------------
1) کل پروژه را در مخزن خصوصی/مورد اعتماد نگه دارید و فایل‌های حاوی داده واقعی را منتشر نکنید.
2) سرویس Render را از render.yaml بسازید و هزینه پلن و Persistent Disk را بررسی کنید.
3) ORIGIN را دقیقاً برابر origin سایت فرانت‌اند (scheme + host، بدون مسیر) قرار دهید.
4) RP_ID را فقط hostname همان دامنه قرار دهید؛ بدون https و بدون مسیر.
5) ALLOWED_ORIGINS را به فهرست دقیق دامنه‌های مجاز محدود کنید.
6) DATA_DIR باید داخل mountPath دیسک پایدار باشد. از /tmp برای داده پایدار استفاده نکنید.
7) URL واقعی API را در config.js قرار دهید.
8) پس از Deploy، /health را بررسی کنید و ورود/ثبت‌نام محلی، فاکتور، خروجی پشتیبان و بازیابی را روی یک کپی آزمایشی تست کنید.
9) تا زمان پیاده‌سازی ثبت‌نام/ورود سروری، کوکی نشست HttpOnly، CSRF protection، کنترل مالکیت داده در سمت سرور و آزمون امنیتی مستقل، اطلاعات مالی واقعی یا چندکاربره وارد نکنید.

این گزارش تضمین امنیت یا گواهی ممیزی نیست؛ صرفاً شرح تغییرات و محدودیت‌های شناخته‌شده همین بسته است.
