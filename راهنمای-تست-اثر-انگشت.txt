فاکتورینو — بسته آزمایشی رفع خطای «ارتباط امن برقرار نشد»
========================================================

این بسته شامل فرانت‌اند اصلاح‌شده و سرور WebAuthn است. چون سایت فعلی روی GitHub Pages قرار دارد، API باید جداگانه روی یک سرویس Node.js اجرا شود.

مرحله ۱ — انتشار سرور آزمایشی
1) وارد Render شو و با کمک والد/سرپرست، یک حساب و سرویس Web Service بساز.
2) تمام فایل‌های داخل این ZIP را در ریشه همان مخزن GitHub سایت قرار بده و Commit کن؛ به‌ویژه package.json، server.mjs، render.yaml، index.html و config.js باید در ریشه باشند. سپس همان مخزن را به Render متصل کن.
3) در Render یک Web Service از همان مخزن بساز. Root Directory را خالی/ریشه بگذار، Runtime را Node انتخاب کن، Build Command را npm install و Start Command را npm start قرار بده. Node باید نسخه 20 یا جدیدتر باشد. اگر render.yaml شناسایی شد، تنظیمات سرویس و متغیرها را از آن بگیر و بازبینی کن.
4) این متغیرها را در Environment وارد کن:
   ORIGIN = https://mkl173132-dotcom.github.io
   ALLOWED_ORIGINS = https://mkl173132-dotcom.github.io
   RP_ID = mkl173132-dotcom.github.io
   DATA_DIR = /tmp/faktorino-data
   RP_NAME = فاکتورینو
5) Deploy را انجام بده. پس از انتشار، آدرس سرویس شبیه https://نام-سرویس.onrender.com خواهد بود.
6) آدرس https://نام-سرویس.onrender.com/health را باز کن. باید JSON شامل ok:true ببینی.

مرحله ۲ — اتصال سایت GitHub Pages به API
1) پس از Deploy موفق، فایل config.js را در GitHub ویرایش کن.
2) مقدار FAKTORINO_API_BASE_URL را با آدرس واقعی سرویس Render عوض کن؛ مثال:
   window.FAKTORINO_API_BASE_URL = "https://faktorino-webauthn.onrender.com";
   آخر آدرس / نگذار.
3) تغییر config.js را Commit کن. فایل index.html همین بسته نیز باید در ریشه مخزن باشد؛ چون این بسته برای هر دو هاست آماده شده، package.json و server.mjs هم در همان مخزن باقی بمانند.
4) چند دقیقه صبر کن و سایت را با Ctrl+F5 یا در پنجره ناشناس باز کن.

مرحله ۳ — آزمایش
1) سایت را با HTTPS باز کن.
2) با حساب آزمایشی خودت وارد شو.
3) به «حساب و امنیت کاربری» برو و «فعال‌سازی ورود بیومتریک» را بزن.
4) پنجره سیستم‌عامل برای Passkey ظاهر می‌شود. ممکن است گوشی اثر انگشت، تشخیص چهره یا PIN قفل صفحه بخواهد.
5) خارج شو و ورود بیومتریک را امتحان کن.

اگر خطا دیدی:
- آدرس /health را باز کن؛ اگر باز نمی‌شود، سرور Deploy نشده یا خواب است.
- مطمئن شو config.js آدرس درست Render را دارد.
- مقادیر ORIGIN و ALLOWED_ORIGINS باید دقیقاً https://mkl173132-dotcom.github.io باشند.
- مقدار RP_ID باید دقیقاً mkl173132-dotcom.github.io باشد.
- از HTTPS استفاده کن و مرورگر را به‌روز نگه دار.

محدودیت‌های مهم این بسته آزمایشی
--------------------------------
- GitHub Pages فقط سایت ثابت را میزبانی می‌کند؛ API روی Render اجرا می‌شود.
- پلن رایگان Render ممکن است پس از بی‌کاری بخوابد و شروع درخواست بعدی چند لحظه طول بکشد.
- این تنظیم آزمایشی از فایل دیتابیس موقت /tmp استفاده می‌کند؛ ممکن است با Restart یا Deploy اطلاعات Passkey پاک شود. برای استفاده پایدار باید دیتابیس دائمی و پشتیبان امن تنظیم شود.
- بسیار مهم: حساب‌های فعلی فاکتورینو در مرورگر محلی هستند. سرور آزمایشی هنوز ورود/ثبت‌نام اصلی فاکتورینو را به نشست امن سروری وصل نمی‌کند و مالکیت حساب را احراز نمی‌کند. بنابراین این نسخه فقط برای آزمایش فنی Passkey با حساب آزمایشی است؛ برای حساب واقعی، داده مالی، مشتری یا انتشار عمومی امن نیست.
- هرگز رمز GitHub یا کلید خصوصی را در فایل‌ها یا چت قرار نده.
- اثر انگشت خام به وب‌سایت فرستاده نمی‌شود؛ سیستم‌عامل تأیید Passkey را انجام می‌دهد.
